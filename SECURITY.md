# CarAfford Security Policy & Architecture

Security is a primary design tenet of the **CarAfford** platform. This document describes the security controls, authentication/authorization architecture, and hardening measures implemented across the application.

---

## 1. Authentication & Authorization

### JWT Token Architecture
- **Algorithm**: `HS256` HMAC SHA-256 with cryptographically strong secret keys.
- **Access Tokens**: Short-lived (60 minutes default), containing user ID, email, role, and expiration timestamp.
- **Refresh Tokens**: Long-lived (7 days default) used for seamless token rotation via `POST /api/v1/auth/refresh`.
- **Password Hashing**: Industry-standard **bcrypt** with salted hashing. Raw passwords are never logged or stored.

### Role-Based Access Control (RBAC)
- **`USER`**: Standard consumer role with access to calculation engines, recommendation tools, and public catalogue data.
- **`ADMIN`**: Privileged operational role required to access administrative portals (`/admin`), trigger data ingestion jobs (`/api/v1/admin/ingest/*`), inspect data quality, and view system audit logs (`/api/v1/admin/audit-logs`).
- Protected endpoints enforce RBAC via FastAPI dependency injection (`Depends(require_admin)`).

---

## 2. API & Network Security

### HTTP Security Headers
Every HTTP response generated by the FastAPI backend and NGINX reverse proxy includes mandatory security headers:
- `X-Content-Type-Options: nosniff` (Prevents MIME-sniffing)
- `X-Frame-Options: DENY` (Mitigates clickjacking attacks)
- `X-XSS-Protection: 1; mode=block` (Enforces legacy browser XSS filters)
- `Strict-Transport-Security: max-age=31536000; includeSubDomains; preload` (Enforces HTTPS)
- `Referrer-Policy: strict-origin-when-cross-origin`

### Rate Limiting & DDoS Protection
- Distributed Redis token bucket / sliding window rate limiting.
- Configurable per-IP rate limits (default: **120 requests/minute**).
- Public pricing, calculation, and authentication endpoints are protected against automated scraping and brute-force abuse.
- Rate-limited requests receive standardized `HTTP 429 Too Many Requests` responses.

---

## 3. Audit Logging & Provenance

- Sensitive administrative actions (catalogue updates, tax rule edits, manual ingestion triggers, user role modifications) automatically generate immutable entries in the `audit_logs` table.
- Audit records capture:
  - Performing User ID
  - Action Category & Event Name
  - Resource Type & Resource ID
  - Client IP Address & User-Agent
  - Payload Changes (Before / After diffs in JSON format)
  - Execution Timestamp

---

## 4. Vulnerability Reporting

If you discover a security vulnerability in CarAfford, please contact the security team at `security@carafford.in`. Please include detailed steps to reproduce the issue.
